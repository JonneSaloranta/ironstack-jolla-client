# Compatibility with IronStack

How the app's training features line up with IronStack's web UI and its
REST API (`/api/v1/`, checked against IronStack 1.31.0 and its dev
branch of 2026-11-04 - #47-#51 and the assistant's recipes, not released
yet - and `docs/api/openapi-v1.yaml` there; the app needs 1.31.0 or
later and uses the dev branch's additions when the server has them). Scope:
training, body measurements, activities, stretching, nutrition, friends
and groups, coaching, the AI assistant and the guided tours.

Status: **done**, **todo**, or **n/a** (not possible over the API; listed
so it isn't rediscovered).

## API usage

| Item | Status | Notes |
|---|---|---|
| `Idempotency-Key` on queued `POST`s | done | One UUID per queued write, kept on disk with it, so a retry after a lost response doesn't log anything twice. Sets, finishing a workout, diary entries, body measurements, activities and stretching quick logs are queued; a rejected one (4xx, `422` included) is dropped and reported with a notification. |
| `new_records` on `POST sets/` | done | The "New PR" notification. |
| Filters (`diary-entries/?date=`, `date_after=`, `measurements/?measurement_type=`, `recorded_after=`, `activities/?activity_type=`) | done | A day's diary, the statistics' range, a type's history, the dashboard's body weight, the weight trend. The type lists (body tracking, activities) still read every row once: a request per type would be one per type on every visit, against the rate limit. |
| `foods/?search=` | done | Food search (name, brand, barcode). Recipes are still searched locally, by their translated name. |
| `display_name` and the other `display_*` twins | done | Every built-in name and text is shown from its twin (`display_name`, `exercise_display_name`, `display_instructions`, ...; `Store.shown`, `Texts.shownText`). Each request sends the phone's language, then English, as `Accept-Language`, so they match the app's language rather than the IronStack profile's. IronStack's dev branch (after 1.31.0, #47) adds the last ones - `up-next/`'s program, a stretch session's name, the coaching client page, shared plans - and the app shows them; until that's released, and for data cached by an older version, the app keeps its copy of the web's catalog (`content.js`, `content_texts.js`). |
| `sessions/<id>/cooldown/` | done | The cool-down card on a finished workout, in one request. |
| `nutrition/stats/`, `nutrition/maintenance/` | done | The statistics page (`?range=30d`, with every fixed period) and the dashboard's observed maintenance. The maintenance explanation is written in the app from the figures, in the phone's language and weight unit; the server's `reason` (in the profile's language) is shown only for a case the app doesn't know. |
| `exercise_name` on prescriptions, performed exercises and records | done | No per-id `exercises/<id>/` lookups any more. |
| `sessions/?status=` | done | Dashboard asks for `in_progress` directly instead of scanning the newest page. |
| `exercises/?page_size=100` | done | Fewer requests for the exercise picker. |
| `exercises/?search=` | n/a | Deliberately not used: it matches names in the IronStack profile's language, the app shows them in the phone's. The picker searches the whole list locally, by the name as shown and as stored. |
| `exercises/<id>/last-performance/` | done | "Last time" per exercise, instead of searching the newest page of sessions. |
| `performed-exercises/<id>/suggestion/` | done | Shown in training mode and used as the first set's default, like the web. |
| `up-next/` | done | Dashboard "Up next" card with one tap to start it. |
| `analytics/achievements/` | done | Dashboard, one at a time, moving on every 4.5 s like the web's carousel (or on a tap). Shown to everyone, as on the web; the server already leaves out people who opted out. |
| Ignore unknown response fields | done | Required by IronStack's versioning rules; the app only reads the fields it knows. |

## Behaviour that should match the web

| Item | Status | Notes |
|---|---|---|
| Built-in content names translated | done | The server stores built-in names (exercises, programs, workouts, measurement and activity types, stretches, meal slots, recipes) in English and the web translates them with its own catalog (`apps/*/i18n_content.py` + `locale/*/django.po`). The API sends them translated as `display_*` twins (IronStack #36, #42), in the phone's language; where a 1.31 server has none (IronStack #47, fixed on its dev branch) the app falls back to the same translations, generated by `tools/content-i18n/generate.py` (`content.js` for names, `content_texts.js` for instructions). Custom names are shown as typed. |
| A missing API key permission explained | done | A 403 names the context and permission to add (e.g. "nutrition - Create"), see `ApiClient::contextForPath`. |
| Default for the next set | done | Same order as the web (`apps.workouts.views._build_set_form`): last set this session, then the smart suggestion (first set only), then the plan's target with `min_reps`. Two additions: after warm-ups only, the first working set's default is used instead of repeating the warm-up, and "last time" fills in when there's nothing else (the web leaves it empty). |
| Smart suggestion shown | done | "Suggested: 52.5 kg x 5 - High confidence" and the reason, until the first working set is logged; in training mode and the full view. The reason text comes in the IronStack profile's language. |
| Per-hand weights | n/a | The web doesn't mark them when logging either (only on the exercise page), so neither does the app. |
| Exercise library | done | Browse, search (shown and stored name) and filter by primary muscle group like the web; muscle groups, equipment, movement type and weight logging shown translated. |
| Exercise guide (description, instructions, images) | done | `exercises/<id>/`, instructions translated (`display_instructions`); opened by tapping the exercise's name in training mode or the full view, like the web's guide button. |
| Own exercises | done | Create, edit, deactivate (`DELETE` is a soft delete, like the web's Deactivate). Images: added from the gallery with an optional caption (scaled to 1600 px first, like the server does) and removed by press and hold (`exercises/<id>/images/`, IronStack #48 - dev branch, after 1.31.0; a 1.31 server answers with a message to use the web). Needs the Pictures and Media index permissions. |
| Records for an exercise | done | On the exercise page (`records/`, filtered here). |
| Strength trend | done | Estimated 1RM per training day, sessions and volume for the web's date ranges (`analytics/exercises/<id>/`). |
| New personal record shown after logging a set | done | A notification like the web's toast: "New PR - <exercise>" and each record, from the set's `new_records` once a queued set reaches the server. |
| Deleting a workout from history | done | `DELETE sessions/<id>/` (records are rebuilt by the server, like the web's delete). |
| Summary period | done | Dashboard: 7 days, 30 days or all time (`analytics/summary/?range=`); tap the heading. "This week" (Monday through today, like the web) too once the server answers with the `range` it covered (`?range=week`, IronStack #49 - dev branch, after 1.31.0). |
| Profile settings | done | Units, language, time zone, height, BMI, sharing activity, friend requests and group invites (`PATCH profile/`). The web-only look (theme, appearance) isn't shown. |
| Duration estimates (a workout before starting it, the time left in training mode) | done | A workout's `estimate` on the program, the workout and up next ("~45min ± 5min", "rough" when the server has little data), `sessions/<id>/remaining-estimate/` beside the elapsed time in training mode (IronStack #50 - dev branch, after 1.31.0; not shown with a 1.31 server). |
| Program editing (programs, workouts, prescriptions) | done | Create, edit and delete your programs; add, edit, reorder (up/down, like the web) and delete workouts and their exercises. Weights in your unit, like the web form. Built-in program descriptions translated like the web. |
| Copying a program template | done | `programs/<id>/copy/`, like the web's Copy. |
| Social, coaching, assistant, tutorials | done | See "Other areas". Friends/groups, coaching and the assistant each need an API key with their own permission area; a 403 names it. |

## Other areas

| Area | Status | Server gaps |
|---|---|---|
| Body measurements | done | Types with their latest reading (body weight first, then by the name as shown); a type's BMI card, statistics, trend and readings; log (through the sync queue, so offline too), correct and delete readings; your own types created and deactivated. Dashboard: body weight and "Log body weight", like the web. The "Time to log your body measurements?" reminder is the server's own rule (`needs_body_tracking_reminder`), switched in Settings with the web's own setting. |
| Activities | done | Types with how many are logged; a type's summary (count, total duration, distance, calories), duration trend and activities; log (duration in minutes and distance in km/mi, like the web form; through the sync queue), correct and delete; your own types created and deactivated. |
| Stretching | done | Home with streak, last 7 days, all time, routines, minutes per week and recent sessions; the stretch library (type and muscle group filters, instructions translated) with your own stretches; routines with their stretches, your own created, edited (stretches added, changed, reordered, removed) and deactivated, built-in ones copied to edit; history with corrections and deletes; log stretching after the fact (through the sync queue). Built-in routines are copied with `stretch-routines/<id>/copy/`. A guided session (get ready, hold per side and set, rest, pause, skip) runs on the server like the web's player: started with `stretch-sessions/start/`, each stretch marked done with the seconds held or skipped, then completed or abandoned; one already running is picked up again. Without a connection the routine plays from the phone and is logged as a quick log when finished. The timer chimes like the web's (same tones, generated by `tools/sounds/generate.py`; off in Settings) - this needs the sailjail `Audio` permission, which Sailfish shows as "Play and record audio" although nothing is recorded. A finished workout opens in full with the web's cool-down card: the server's suggestion (`sessions/<id>/cooldown/`) - the trained muscles, a routine or library stretches - started as a session marked as the workout's cool-down, or the cool-down already done after it. |
| Nutrition | done (tried in the emulator 2026-11-03; not yet on the phone) | Overview (today vs. target, goal, today's plan); food diary by day (`?date=`) with meals, totals from each entry's logged `nutrition`, food/recipe/quick entries (new ones through the sync queue, shown as "Not sent yet" until they reach the server), edits, deletes, copy day (`diary-entries/copy-day/`), save meal as recipe; foods with the full label and your own foods, searched on the server; recipes with ingredients, your own and the built-in ones (read only, like the web); goal, target and nutrition profile - the profile set up and corrected, a new goal started with a calculated target (`POST nutrition-goals/`); diet plans generated, activated, applied to a date, renamed, deleted, with the shopping list, shopping days and ticks kept per plan and trip like the web's, their recipes opening with their ingredients; the web's calculators. "Is your current target working?" is the server's `nutrition/adjustment-suggestion/` (text in the IronStack profile's language), accepted with a button. Statistics like the web's (last 30 days, the fixed periods, daily calories with the target line) and the observed maintenance from the server (`nutrition/stats/`, `nutrition/maintenance/`); today's totals from `nutrition/daily-totals/`. Open Food Facts: searched and imported through the server (`foods/search-off/`, `foods/import-off/`), so a product keeps its Nutri-Score, NOVA group and OFF link and the server's OFF budget applies; the phone never talks to Open Food Facts itself. A barcode can also be scanned with the camera (EAN-13, EAN-8, UPC-E - what food packages carry), read by the app's own decoder (`src/barcode.cpp`), so no barcode library is bundled; it needs the sailjail Camera permission. Cover (no workout in progress): today's calories against the target with a bar, protein (`nutrition/daily-totals/`), and a quick entry action; read when the cover comes into view. |
| Training analytics over time | done | The web's Progress page for the web's date ranges: workouts, training time and volume (`analytics/summary/`), weekly and muscle-group volume (`analytics/volume/`, `analytics/muscle-groups/`), strength trend per exercise, body measurement changes and records grouped by exercise (rep records behind "Show more") - the last two worked out here from `measurements/` and `records/`. |
| Friends and groups | done | Friend requests and group invites to answer; friends and groups with their unread counts; conversations (last 100 messages, new ones asked for every 10 s while open - the API has no push); add a friend by username, mute, remove, block and unblock; groups created, joined with a code, edited, friends invited, the invite code switched and renewed, roles changed, ownership handed over, left and deleted. Every rule is the server's; its message is shown. The dashboard has the web's "Recently active" list. Not here: push notifications (Sailfish has no web push). |
| Coaching | done | Ask a trainer, answer requests, end coaching; plans a coach shared, imported as your own copy, and the coach's newer version taken on that copy ("Update from coach" on the program or diet plan). A personal trainer sees their clients (last 30 days, highlights, body measurements, records, the shared programs they use) and chooses who a program or diet plan is shared with. The update shows the server's diff first; it replaces the copy's workouts, keeping its name and description. Becoming a trainer and accepting new requests are switches at the bottom of the coaching page (`profile/`, IronStack #51 - dev branch, after 1.31.0; hidden with a 1.31 server). A coach's own shared programs aren't listed under Programs (like the web). A coach's edits in the app offer clients the update, like the web's (IronStack 1.31). |
| AI assistant | done | What turning it on means is shown first, with the web's own wording; then conversations, replies followed every 1.5 s while the server writes them (with what it's doing), Markdown shown as simple formatting, the diet plans, programs and recipes it suggests created (a plan or program inactive; each opened for review) or dismissed, a recipe with its servings and calories per serving; settings for what it may read, "about you", and with your own key its model and effort. The key itself is set on the web only, as the API asks. |
| Guided tours | done | The web's tours are tied to the web's page elements, so the app shows them as a Guide to read by section; opening one marks it done (shared with the web). Settings switches the web's automatic tours. |
